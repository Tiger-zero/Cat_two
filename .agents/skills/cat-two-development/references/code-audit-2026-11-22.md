# Cat_two 代码审计 · 2026-11-22

审计覆盖单人 SQLite 部署中的网页登录、REST 和 Connect、笔记与 ZIP 写入、消息收件及 `/mcp`。以下记录存储改造后审计时观察到的行为。后续修复与验证见开发记录。 [开发记录](../SKILL.md#开发记录)

## P1 · 公网登录与笔记完整性

### 登录页执行实例自定义脚本

`GENERAL` 是登录前加载的设置。网页根组件会把其中的自定义 JavaScript 插入页面，登录路由也使用该根组件。管理员 PAT 在服务端按管理员授权，可以修改该设置；当前 HTML 安全策略未限制内联脚本。管理员 PAT 泄露时，风险由 API 读写延伸到用户下一次网页登录及浏览器会话。这需要先取得管理员配置权限。 [设置授权](../../../../server/api/instance_service.go#L207) · [登录前的设置](../../../../server/api/acl_config.go#L50) · [脚本加载](../../../../web/src/App.tsx#L38) · [安全响应头](../../../../server/frontend/frontend.go#L87)

建议停用单人模式的任意脚本，保留标题、Logo 等声明式配置。发布时先用浏览器验证登录、编辑器和笔记渲染，再启用约束 `script-src` 的 CSP。验收覆盖安装升级时旧脚本不执行、管理员 PAT 无法再写入脚本，以及网页登录和两步验证正常。

### 创建操作的重试与导入状态

Web 新建笔记没有传入稳定的 `memoId`。API 在正文和附件绑定提交成功后还会读取附件与关系。若响应途中丢失或后续读取失败，用户再次保存时可能新增重复笔记。使用同一 ID 重试的客户端能避免创建第二条，但当前只收到冲突，仍要查询原保存结果。Telegram 和企业微信已经通过投递 ID 实现了自己的去重。 [Web 创建请求](../../../../web/src/hooks/useMemoQueries.ts#L308) · [创建后读回](../../../../server/api/memo_service.go#L40) · [消息去重](../../../../server/api/memo_capture.go#L61)

ZIP 新建同样有提交边界问题。正文和附件先保存，归档与置顶状态另行写入。这次状态写入失败时，导入报告可能将已存在的笔记列为失败，按「保留已有」重试又会跳过该条。 [ZIP 创建和状态写入](../../../../server/api/user_service_memo_import.go#L208)

建议为 Web 草稿保存稳定的创建 ID。为 REST 和 MCP 定义可选的幂等重放约定，按所有者、操作 ID 和原请求摘要核对，确认同一次提交时返回已有资源。把 ZIP 的归档和置顶状态放入初次保存的事务。验收时模拟响应丢失、相同 ID 不同正文和导入重试，核对笔记数、附件绑定、归档状态与变更通知。

### Web 与 MCP 并发编辑可能覆盖正文

Web 保存前用一次 GET 检查草稿基线，随后发送更新。服务端的事务比较的是本次更新请求开始时读取的正文。若另一端在这两步之间已完成修改，后到的写入可以把已经保存的正文覆盖。用户可编辑的秒级 `update_time` 不适合充当版本号。 [草稿检查与提交](../../../../web/src/components/MemoEditor/edit/hooks/useMemoSave.ts#L89) · [更新时读取当前记录](../../../../server/api/memo_service.go#L277) · [事务比较的版本](../../../../server/api/memo_attachment_service.go#L238)

建议引入独立的笔记修订号，在同一 SQLite 事务内检查并推进。让 Web、REST 和 MCP 可以带上读取时的修订号，逐步保留旧客户端兼容。遇到冲突时保留待提交草稿和附件。用两端先后提交不同内容、附件和归档操作验证。

## P2 · 会话、MCP 权限与内部调用

### 退出登录与续期使用不同的令牌标识

退出只撤销本次请求 Cookie 里的刷新令牌 ID，并忽略撤销写入错误。若续期已先换发新 ID，退出可能遗漏同一次登录的后续刷新令牌。访问令牌校验绑定密码与账户会话版本，普通退出不会立即作废已经签发的访问令牌，剩余有效期最多 15 分钟。 [退出和续期](../../../../server/api/auth_service_session.go#L64) · [刷新令牌轮换](../../../../store/user_setting.go#L182) · [访问令牌校验](../../../../server/auth/authenticator.go#L53) · [访问令牌时长](../../../../server/auth/token.go#L41)

建议为每次登录分配稳定的会话 ID，在同一会话内轮换刷新凭据。退出以会话 ID 原子撤销，同时通知其他标签页。验收应覆盖退出与续期交错、持久化失败、旧会话的处置以及其他设备的有效会话。

### MCP 令牌有效期已隔离，工具权限仍然统一

专用令牌经过有效期与撤销检查，普通 PAT 无法代替它直接连接。所有有效 MCP 连接目前都获得同一个工具集，包括创建和更新。用于只读查询的客户端也实际持有写权限。 [令牌签发和鉴权](../../../../core/mcpconnection/connection.go#L33) · [个人工具清单](../../../../server/mcp/service.go#L132)

建议新增可选的「只读」和「读写」授权，读写仍为默认以维持现有接入方式。工具发现按权限返回列表，调用时再强制校验具体工具。延续到期或撤销后的下一次请求即生效，并检查调用方不能通过未列出的工具名称进行写入。

### MCP 请求限流与业务逻辑跨两条路径

连接鉴权在 `/mcp` 路由中先执行，工具级限流在鉴权后生效。具有 MCP 令牌前缀的错误请求也会触发 SQLite 查询，协议握手和工具发现未覆盖同一限流。已有工具又分成直接读取 Store 和经 HTTP 适配器调用 REST 两类。后者会额外编码、执行路由和解码，直接调用路径需单独维护访问与分页规则。 [路由和鉴权](../../../../server/mcp/service.go#L221) · [工具限流](../../../../server/mcp/service.go#L142) · [连接记录读取](../../../../core/mcpconnection/connection.go#L88) · [HTTP 适配器](../../../../server/mcp/adapter.go#L29) · [直接批读](../../../../server/mcp/personal_batch.go#L79)

建议在鉴权前按可信客户端 IP 设置协议入口预算，认证后保留共享的读写预算，并给批量读取加总字节限制。逐步让 REST、Connect 和 MCP 共用有类型的笔记操作，由同一处处理所有权、来源、版本和错误语义。重构时沿用现有 MCP 工具名与输入输出，使用三种接口的等价用例守住权限、排序、标签、分页和撤销规则。再用并发握手与典型大正文的基准测试衡量 SQLite 查询数、响应体积和请求延迟。

## 修复与验证 · 2026-11-22

- 停用实例自定义 JavaScript，启用网页脚本 CSP。会话刷新沿用稳定的会话 ID，退出和撤销作废该会话的访问及刷新凭据，并同步同一会话的其他标签页。SSE 在后续事件和心跳时复验凭据。验证了旧 Cookie 升级、持久化失败、并发续期、会话撤销和桌面两步登录。 [会话测试](../../../../server/api/test/auth_session_rotation_test.go) · [升级测试](../../../../server/test/session_upgrade_test.go)
- 新建笔记和评论支持用固定 ID 重放相同请求。Web 保存草稿时记录提交快照。原子事务检查笔记修订号，冲突时保留正文和附件供复核。ZIP 新建的置顶、归档与正文及附件绑定一同提交。 [笔记测试](../../../../server/api/test/memo_write_test.go) · [跨接口验证](../../../../server/test/mcp_memo_write_test.go)
- MCP 令牌可选只读或读写，既有连接按读写迁移。工具发现及调用都校验权限。按可信客户端 IP 和账户限流，单批 Markdown 上限为 4 MiB。个人模式直接调用 Web、REST 和 Connect 使用的笔记服务。 [MCP 限额与工具](../../../../server/mcp/README.md)
- 本地 SQLite 热缓存测量使用环回 HTTP 并启用限流。64 次握手分给 8 个并行工作线程，p95 为 5.72 ms，每次执行一次令牌查询。8 次顺序批读各取 2 MiB Markdown，p95 为 145.93 ms，每次执行两次查询，完整 MCP 响应约 4.2 MB。查询数来自临时测试驱动计数。该测量用于记录本地验收的请求成本。
- SQLite 全量、服务端竞态测试、前端 1,363 项测试、类型检查、静态检查和生产构建通过。本地 AMD64 镜像从 `0.09` 升级后，旧登录可续期，注销后的新凭据被拒绝，旧笔记和附件可读取。Chromium 模拟服务器已保存但浏览器丢失响应，刷新并重试后只有一条笔记。
