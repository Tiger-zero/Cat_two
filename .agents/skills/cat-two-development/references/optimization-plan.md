# Cat_two 优化方案

Cat_two 的主要工作流是记下内容、按日期和标签找回、在 NAS 保留可恢复的数据，再由 Codex 整理知识。优先保证笔记、附件和时间能可靠保存，其次缩短检索和日常操作。新功能沿用单账户产品定位和现有权限边界。 [功能与实现](product-guide.md)

## P0 · 验证完整实例恢复

**现状**　容器冒烟测试可验证镜像启动和升级，文件级备份还需要覆盖 NAS 上的实际挂载和附件存储。SQLite 数据目录中的配置、签名密钥、两步验证和令牌会一起恢复到快照时点。 [NAS 配置](../../../../compose.nas.yaml) · [备份步骤](../../../../README.md#备份和升级) · [服务端初始化](../../../../server/server.go)

**方案与验收**　停止测试源实例做全量备份，或使用一致性快照。用独立 Compose 项目、备份副本和独立附件存储恢复，测试端口限制在本机。检查数据库完整性，并核对笔记、归档、回收站、登录及两步验证、附件字节和 MCP 工具。记录快照回到较早时点时哪些令牌需要重新撤销。用同一份隔离数据做下一版升级前后的对照。 [镜像冒烟流程](../../../../scripts/release_smoke_test.sh)

## P1 · 保证记录与恢复的可靠性

1. **保留手动填写的笔记时间。** 在当前前端和隔离 SQLite 实例中已复现，历史日草稿设置时间后，提交文字搜索会在日期不变的情况下重置时间。按上海日期派生日历默认值，只在实际切换日期时同步默认时间，保留本次编辑中的手动值。覆盖同日文字和标签筛选、跨日切换，以及按创建时间或更新时间筛选。 [日期入口](../../../../web/src/pages/Home.tsx) · [编辑会话](../../../../web/src/components/MemoEditor/edit/EditSession.tsx)
2. **保护已有笔记的编辑和待上传附件。** 隔离浏览器已复现刷新后正文恢复、待上传附件消失。已有笔记的编辑也关闭了草稿保存。优先在可能丢失修改时提示，再按账号、笔记和基准版本恢复未保存的正文。有需要时用 IndexedDB 做本机附件暂存。验证意外刷新、纯附件草稿、重新打开、取消和保存成功，并处理多标签页里的较新版本。 [草稿保存](../../../../web/src/components/MemoEditor/edit/hooks/useAutoSave.ts) · [编辑会话](../../../../web/src/components/MemoEditor/edit/EditSession.tsx)
3. **补齐 ZIP 往返恢复。** 导入已归档父笔记的评论时，正常状态校验可能阻止评论恢复。导出的大附件也可能触发导入器的整包解压比限制。可在导入流程中给同一作者恢复评论，再提交父笔记的最终归档状态。对可能触发比例上限的附件考虑使用 ZIP Store，继续保留输入端的解包限制。验收应涵盖归档评论、附件哈希和三种冲突处理，并验证已有 ZIP 仍可导入。 [评论规则](../../../../store/memo_comment.go) · [导入](../../../../server/api/user_service_memo_import.go) · [ZIP 读写](../../../../core/memoexport/)
4. **让回收站清理失败可重试。** 永久删除会先提交数据库变更，再清理本地或 S3 文件，清理失败时笔记可能已经移除。将待清理记录随删除持久化，按已有附件归属校验执行可重试清理，并在界面准确显示删除结果。用存储故障注入验证进程重启后可重试，覆盖手动删除和 30 天定时清理。 [回收站处理](../../../../server/api/memo_trash_handler.go) · [附件故障测试](../../../../server/api/test/attachment_service_test.go)

## P2 · 改善查找和 SQLite 查询

1. **让搜索可以指定归档范围。** 首页搜索使用普通笔记范围，归档笔记需要转到归档页。可在搜索面板提供显式范围，沿用关键词、标签和账号过滤。准备相同关键词分别出现在普通和归档笔记的夹具，核对范围及分页结果。 [搜索入口](../../../../web/src/components/AppSidebar/QuickFindDialog.tsx) · [归档页](../../../../web/src/pages/Archived.tsx)
2. **按常用排序评估 SQLite 索引。** 在 1 万条合成笔记上，MCP 普通时间排序和网页置顶优先排序当前都有额外排序，候选索引分别能消除各自的排序步骤。先对实际常用列表做 `EXPLAIN QUERY PLAN` 和耗时对照，再决定索引。核对排序、相同时间戳分页及归档筛选，也要测导入时的写入成本。这轮未测量 NAS 实际耗时。 [SQLite 查询](../../../../store/db/sqlite/memo.go) · [现有索引](../../../../store/migration/sqlite/LATEST.sql)
3. **缩小 MCP 标签统计的读取量。** 标签查询当前分批扫描账号的普通笔记并读取完整元数据。可投影笔记 ID 和标签，沿用现有筛选条件。用不同规模的数据比较耗时和内存，并核对祖先标签计数、同一笔记去重、续页和旧数据兼容。令牌有效期与撤销继续沿用现有的每次请求索引校验。 [标签查询](../../../../server/mcp/personal_tags.go) · [连接校验](../../../../core/mcpconnection/connection.go)

## 实施顺序

先建立可重复的恢复夹具，并修复手动时间和草稿行为。接着按往返测试修复导入与附件清理。最后根据实际笔记规模和使用频率决定查询优化的范围。旧账号和旧数据继续沿用所有权隔离，历史功能按实际依赖逐步收敛。 [开发流程](../SKILL.md#开发与验证)
