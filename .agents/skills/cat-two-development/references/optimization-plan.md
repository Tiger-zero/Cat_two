# Cat_two 优化方案

Cat_two 的主要工作流是记下内容、按日期和标签找回、在 NAS 保留可恢复的数据，再由 Codex 整理知识。优先保证笔记、附件和时间能可靠保存，其次缩短检索和日常操作。新功能沿用单账户产品定位和现有权限边界。 [功能与实现](product-guide.md)

## P0 · 验证完整实例恢复

**现状**　容器冒烟测试可验证镜像启动和升级，文件级备份还需要覆盖实际使用的命名卷或 NAS 绑定目录及附件存储。SQLite 数据目录中的配置、签名密钥、两步验证和令牌会一起恢复到快照时点。 [Compose 配置](../../../../compose.yaml) · [备份步骤](../../../../README.md#备份和升级) · [服务端初始化](../../../../server/server.go)

**方案与验收**　停止测试源实例做全量备份，或使用一致性快照。用独立 Compose 项目、备份副本和独立附件存储恢复，测试端口限制在本机。检查数据库完整性，并核对笔记、归档、回收站、登录及两步验证、附件字节和 MCP 工具。记录快照回到较早时点时哪些令牌需要重新撤销。用同一份隔离数据做下一版升级前后的对照。 [镜像冒烟流程](../../../../scripts/release_smoke_test.sh)

## P1 · 记录与恢复

1. **保留手动填写的笔记时间。** 日历默认时间按上海日期更新。同一天修改文字搜索和其他筛选时，已编辑的时间保持有效。真正切换日期时刷新日历默认值。回归覆盖同日筛选、跨日切换、刷新和按创建时间或更新时间筛选。 [日期入口](../../../../web/src/pages/Home.tsx) · [编辑会话](../../../../web/src/components/MemoEditor/edit/EditSession.tsx)
2. **保护已有笔记的编辑和待上传附件。** 草稿保存到当前浏览器，已有笔记按账户、笔记和编辑基准匹配后恢复。附件以原文件暂存在 IndexedDB，恢复后重新构建预览，保存成功后清除。回归覆盖刷新、纯附件草稿、取消编辑和其他会话更新笔记后的冲突提示。 [草稿保存](../../../../web/src/components/MemoEditor/edit/hooks/useAutoSave.ts) · [待上传附件](../../../../web/src/components/MemoEditor/edit/hooks/useStagedDraftFiles.ts)
3. **补齐 ZIP 往返恢复。** 导入时可在仍归同一作者的归档父笔记下还原评论。新 ZIP 直接存储附件字节，导入端继续检查解包限额。测试覆盖同标识的跳过、覆盖、创建副本，以及 80 MiB 高压缩比附件的 SHA-256。新归档的易压缩附件可能占用更多空间。 [评论规则](../../../../store/memo_comment.go) · [导入](../../../../server/api/user_service_memo_import.go) · [ZIP 测试](../../../../core/memoexport/expansion_test.go)
4. **重试回收站清理。** 永久删除的事务同时保存附件待清理记录。接口返回笔记删除结果，清理失败可在之后的后台清扫中重试。测试模拟文件清理失败，关闭并重新打开 SQLite，再验证重试及共享文件引用。 [回收站处理](../../../../server/api/memo_trash_handler.go) · [重开与清理测试](../../../../server/api/memo_trash_handler_test.go)

## P2 · 查找与查询

1. **搜索范围。** 搜索面板支持「未归档」和「归档」。在两个列表间切换时保留日期、标签和当前视图条件，并复用现有列表的账号校验。已用 Chromium 和隔离数据走查两个范围、翻页、浏览器返回以及 360px 窄屏。 [搜索入口](../../../../web/src/components/AppSidebar/QuickFindDialog.tsx) · [导航测试](../../../../web/tests/quick-find-navigation.test.tsx)
2. **SQLite 列表索引。** 新增部分索引，覆盖按所属账号、归档状态和置顶优先创建时间排序的默认列表。验证排序、相同时间戳、分页和旧库迁移。在 5.5 万条合成笔记中，首页首屏 SQL CPU 时间中位数从约 31.7 毫秒降至 0.58 毫秒，每行插入约增加 2 微秒。查询计划取决于 SQLite 的实际数据分布和统计信息。 [SQLite 查询](../../../../store/db/sqlite/memo.go) · [增量迁移](../../../../store/migration/sqlite/26.11/05__add_memo_owner_pinned_created_index.sql)
3. **MCP 标签读取。** 按账号使用一次流式查询读取每篇有效笔记的标签数组，省去反复分页、排序和整份笔记元数据解码。祖先标签计数、去重、分页和原访问控制沿用现有行为。以 SQLite 中 1 万及 5 万条合成笔记、各执行 3 次取中位数，单独测量数据库到 Go 的读取时间，约从 1.13 秒降到 27 毫秒和从 32.8 秒降到 415 毫秒。NAS 的实际耗时需以部署数据测量。 [标签工具](../../../../server/mcp/personal_tags.go) · [查询与隔离测试](../../../../store/test/memo_test.go)
